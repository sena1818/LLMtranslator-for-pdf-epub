# 📘 本地运行指南

## 🎯 快速开始（5 分钟上手）

### 第 1 步：安装 Python 依赖

```bash
# 确保在项目根目录
cd /Users/sena/Desktop/LLMAgent/translator

# 安装依赖
pip install -r requirements.txt
```

### 第 2 步：检查 API 密钥

检查 `.env` 文件是否包含你的 API 密钥：

```bash
cat .env
```

应该看到：
```
SILICONFLOW_API_KEY=sk-**********
```

✅ **你的 API 密钥已经配置好了！**

### 第 3 步：准备翻译文件

有两种方式：

#### 方式 1：翻译已有的 Markdown 文件（推荐新手）

```bash
# 把你要翻译的 .md 文件放到 input/ 文件夹
# 例如：input/mybook.md

# 运行翻译（跳过格式转换）
python translate.py input/mybook.md --skip-conversion
```

#### 方式 2：翻译 PDF 或 EPUB 文件

```bash
# 把 PDF/EPUB 文件放到 BookTrans/ 文件夹
# 例如：BookTrans/mybook.pdf

# 运行翻译（自动转换 + 翻译）
python translate.py BookTrans/mybook.pdf
```

### 第 4 步：查看翻译结果

```bash
# 翻译完成后，文件会保存在 output_final/ 文件夹
# 文件名格式：{原文件名}_CN.md

ls output_final/
```

### 第 5 步：Web 模式（可选）

```bash
# 推荐：长任务模式（后台 API + 独立 worker + 防休眠）
bash scripts/longrun.sh

# 默认：API + 内联 worker
python run_server.py

# 独立 worker 模式
TRANSLATION_INLINE_WORKER=0 python run_server.py
python run_worker.py

# 多进程 worker 集群
python run_worker.py --processes 4 --parallel-tasks 2
```

如果你要翻整本书，优先用 `bash scripts/longrun.sh`。  
它会把 API 和 worker 拆成两个后台进程。

如果你确实需要防止 Mac 休眠，再显式启用：

```bash
TRANSLATION_PREVENT_SLEEP=1 bash scripts/longrun.sh
```

## 📂 文件放置位置

### 输入文件（要翻译的文件）

| 文件类型 | 放置位置 | 说明 |

## ⚙️ 配置修改

所有配置在 `config/config.yaml` 文件中。

### 调整并发数（提高速度）

编辑 `config/config.yaml`：

```yaml
concurrency:
  max_concurrent_requests: 20    # 增加到 20（从 10）
  rate_limit_per_minute: 400     # 增加到 400（从 200）
```

### 降低并发数（网络不稳定时）

```yaml
concurrency:
  max_concurrent_requests: 5     # 降低到 5
  rate_limit_per_minute: 100     # 降低到 100
```

### 调整翻译创造性

```yaml
api:
  translator:
    temperature: 0.5  # 更有创造性（默认 0.3）
    # 或
    temperature: 0.1  # 更保守、准确（适合技术文档）

worker:
  inline_enabled: true
  poll_interval_seconds: 2
  stale_after_seconds: 900
  max_parallel_tasks: 1
  processes: 1

multi_agent:
  enabled: true
  analyst_max_chars: 12000
```

## 📖 术语表使用

### 术语表格式

`data/glossaries/glossary.json`：

```json
{
  "English Term": "中文译名 (English Term)",
  "Hyperstition": "超虚构 (Hyperstition)",
  "War Machine": "战争机器 (War Machine)",
  "Assemblage": "配置 (Assemblage)"
}
```

### 使用术语表

```bash
# 使用默认术语表
python translate.py input/mybook.md --skip-conversion

# 使用自定义术语表
python translate.py input/mybook.md -g data/glossaries/CPglossary.json --skip-conversion

# 不使用术语表
# （暂时把 glossary.json 改名为 glossary.json.bak）
```

### 添加新术语

编辑 `data/glossaries/glossary.json`，添加新的术语对：

```json
{
  "Existing Term": "现有术语 (Existing Term)",
  "New Term": "新术语译名 (New Term)"  // 添加这一行
}
```

## 🐛 常见问题

### 问题 1：找不到模块错误

```
ModuleNotFoundError: No module named 'langchain_openai'
```

**解决方案**：
```bash
pip install -r requirements.txt
```

### 问题 2：API 密钥错误

```
Error: API key not found
```

**解决方案**：
```bash
# 检查 .env 文件
cat .env

# 如果不存在或内容不对，创建/编辑它：
echo "SILICONFLOW_API_KEY=sk-your-key-here" > .env
```

### 问题 3：文件路径不存在

```
❌ 错误: 输入文件不存在: input/mybook.md
```

**解决方案**：
```bash
# 检查文件是否存在
ls input/mybook.md

# 如果不存在，把文件复制到 input/ 文件夹
cp /path/to/your/file.md input/
```

### 问题 4：翻译速度太慢

**解决方案**：提高并发数

编辑 `config/config.yaml`：
```yaml
concurrency:
  max_concurrent_requests: 15    # 提高并发
  rate_limit_per_minute: 300     # 提高速率
```

### 问题 5：API 速率限制（429 错误）

```
HTTP 429 Too Many Requests
```

**解决方案**：降低并发数

编辑 `config/config.yaml`：
```yaml
concurrency:
  max_concurrent_requests: 5     # 降低并发
  rate_limit_per_minute: 100     # 降低速率
```

## 🎬 完整示例

### 示例 1：翻译一个 Markdown 文件

```bash
# 1. 准备文件
cp ~/Downloads/mybook.md data/input/

# 2. 运行翻译
python translate.py data/input/mybook.md --skip-conversion

# 3. 监控进度（另一个终端）
tail -f logs/translation.log

# 4. 查看结果
cat data/output/mybook_CN.md
```

### 示例 2：使用自定义术语表翻译

```bash
# 1. 编辑术语表
vi data/glossaries/my_terms.json

# 内容：
# {
#   "Deleuze": "德勒兹",
#   "Rhizome": "根茎 (Rhizome)"
# }

# 2. 运行翻译
python translate.py data/input/philosophy.md \
  -g data/glossaries/my_terms.json \
  -o output_final/philosophy_CN.md \
  --skip-conversion
```

### 示例 3：批量翻译多个文件

```bash
# 创建批处理脚本
cat > batch_translate.sh << 'EOF'
#!/bin/bash
for file in input/*.md; do
    echo "翻译: $file"
    python translate.py "$file" --skip-conversion
done
EOF

chmod +x batch_translate.sh
./batch_translate.sh
```

## 🔧 高级功能

### 中断后的处理方式

当前 `translate.py` 主流程已经支持**基于 chunk 缓存的重跑恢复**。如果翻译中途中断，直接重新运行同一条命令即可，系统会优先命中已完成 chunk 的缓存，只继续请求未完成的部分：

```bash
python translate.py data/input/bigbook.md --skip-conversion
```

缓存命中依赖以下条件保持一致：
- 输入内容未变化
- 模型与核心 prompt 版本未变化
- 双语模式与术语表内容未变化

缓存文件默认位于：

```bash
data/translation_cache.db
```

如果你希望强制全量重跑，可以先备份或删除缓存文件：

```bash
# 备份当前缓存
cp data/translation_cache.db data/translation_cache.db.bak

# 或删除缓存后重跑
rm data/translation_cache.db
```
